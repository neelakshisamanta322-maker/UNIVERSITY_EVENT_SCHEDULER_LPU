Security Architecture
Advanced Authentication & Security
Security Mechanisms
PBKDF2-HMAC-SHA256 password hashing — 600,000 iterations (OWASP recommended)
Cryptographically secure 16-byte random salt per account
Individual 2FA OTP — 6-digit, cryptographic SHA-256 hash stored in DB
OTP expiration — 10-minute window · max 3 verification attempts
Gmail SMTP STARTTLS — OTP delivered to individual Admin Gmail inbox
Dynamic OTP routing — Admin 1 OTP → Admin 1 inbox; Admin 2 OTP → Admin 2 inbox
Forgot Password & Reset — email-verified OTP recovery workflow
CSRF protection — double-submit cookie pattern on all state-changing requests
HttpOnly session cookies — not accessible by JavaScript
Rate limiting & CAPTCHA — after 3+ failed login attempts
Public registration — always creates Student role; Admin/Coordinator blocked
DEMO_MODE=false · TESTING_MODE=false in production configuration

How Resource Constraints Influence Scheduling
🏛️ Venue Capacity Matching
Events are matched to venues where capacity ≥ expected_attendance. An event with 100 attendees will not be assigned to a 70-seat classroom.
⏱️ Time-Slot Availability
Each venue and staff member carries an available_slots JSON array. The scheduler intersects event allowed slots with venue and faculty available slots.
🔧 Equipment Availability
Required equipment is tracked by quantity. If an event needs a VR Kit and none are free, it cannot be scheduled in that slot.
🚫 Double-Booking Prevention
Once a venue is assigned to an event in a time slot, no other event can claim that venue-slot combination. This is enforced as a hard constraint.
Scheduling Engine
Intelligent Scheduling Engine — CSP
Constraint Satisfaction Problem (CSP) Framework

The scheduling problem is modelled as a Constraint Satisfaction Problem where events are variables, time-slot + venue combinations are domains, and scheduling rules are constraints. The goal is to find an assignment satisfying all hard constraints while maximising soft constraint quality.

🔴 Hard Constraints (Must Satisfy)
Venue capacity ≥ expected attendance
Venue is available in the assigned slot
No two events share the same venue at the same time
All required staff members are available in that slot
Required equipment is available (not over-committed)
Event duration fits within slot boundaries
Fixed-start events are assigned their prescribed slot
Buffer slots maintained between consecutive bookings
🟢 Soft Constraints (Optimize Quality)
Prefer venues matching required venue type (Auditorium / Lab / Classroom)
Prefer preferred venue ID when specified
Minimize unnecessary schedule gaps between events
Distribute events across departments equitably
Respect preferred start hour when specified
Prioritize high-priority events first
⚙️ Priority Ranking System
Events are ranked before scheduling: high → normal → low. Higher-priority events are scheduled first, claiming preferred slots and venues before lower-priority events.
📋 Conflict Logging
Every event that cannot be scheduled has its conflict type and reason stored in the conflict_logs table, linked to the specific schedule run for analysis.
Optimization
OR-Tools CP-SAT & Scheduling Heuristics
OR-Tools CP-SAT Solver
Google OR-Tools — CP-SAT
Google's Operations Research toolkit provides a state-of-the-art Constraint Programming SAT solver for combinatorial optimization problems, including scheduling.
Models events as Boolean decision variables (event × slot × venue assignments)
Adds hard constraints as linear inequalities to the CP model
Maximizes an objective function rewarding soft constraint satisfaction
Returns a provably feasible schedule or reports infeasibility
CSP Heuristic Fallback (Pure Python)
When OR-Tools is unavailable, a pure-Python backtracking CSP heuristic solver is used. It applies Minimum Remaining Values (MRV) and priority ordering to find a valid assignment without external dependencies.

🔄 Dual-Solver Architecture
The system tries OR-Tools CP-SAT first. If the package is unavailable, it falls back to the built-in CSP heuristic. Both solvers write results to the same schedule_runs table with a solver_type tag.
📊 Solver Comparison API
The /api/schedule/compare endpoint runs both solvers and returns a side-by-side comparison of scheduled counts, unscheduled events and solver quality metrics.

What-If Simulator
What-If Simulation Engine
Simulation Capabilities
Venue Shift — Simulate reassigning an event to a different venue and analyse constraint impact
Time Shift — Move an event to an alternative time slot and check for cascading conflicts
Event Attribute Change — Simulate attendance increase or equipment change
Constraint Preservation — All hard constraints are re-validated in the simulation
Cascade Scheduling — Downstream events that are displaced are re-evaluated
Original Schedule Safe — Simulation never overwrites production schedule data
Diff View — Side-by-side comparison of original vs. simulated schedule

🔑 Key Safety Principle: What-If simulation operates on a deep copy of the schedule state. The original schedule_runs record is never modified during simulation.

Simulation Workflow
1. Original Schedule
Load current production schedule from schedule_runs
↓
2. Hypothetical Change
Admin/Coordinator specifies venue shift, time shift or event modification
↓
3. Recalculate Constraints
Re-run constraint validation on modified schedule copy; detect new conflicts
↓
4. Cascade Analysis
Identify displaced events; determine ripple effects across dependent assignments
↓
5. Alternative Schedule Output
Diff of changes presented; admin reviews before any production apply

Limitations
Project Limitations
Current Limitations
🗄️ SQLite Database Scale
SQLite is well-suited for single-server academic project deployments. For large-scale concurrent production workloads, a client-server database (PostgreSQL) would be more appropriate.
📧 Gmail SMTP Dependency
OTP email delivery depends on internet connectivity, a valid Google App Password and Gmail's service availability. Network outages or account issues prevent OTP delivery.
⏳ OTP Delivery Delay
Email delivery is subject to Gmail's queuing and delivery times. OTPs may experience delays depending on network and mail server conditions.
📦 Optional Package Dependencies
OR-Tools CP-SAT, ReportLab PDF and iCalendar ICS exports require additional Python packages. When unavailable, the system falls back to the CSP heuristic and CSV-only export.
🏭 Production Deployment
Full production deployment requires HTTPS termination, a registered domain, production-grade CORS origins, automated database backups and operational monitoring — not currently configured.
Additional Considerations
⚡ Concurrency
SQLite has write-lock constraints under high concurrent write loads. The current implementation has not been validated under large-scale simultaneous multi-user production workloads.
🤖 AI Capability Boundary
The project implements Scikit-Learn ML models and a rule-based AI assistant. It does not include deep learning, neural networks, or large language model capabilities beyond the implemented scope.
📊 Scheduling Input Quality
Schedule quality depends directly on the accuracy of input data — venue capacities, staff availability slots, and equipment quantities. Incorrect data produces suboptimal or infeasible schedules.
